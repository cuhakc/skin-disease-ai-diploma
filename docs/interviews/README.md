# Interviews

**Hard rule:** do not invent interviewees, quotes, or “typical” clinician opinions. If no interview has happened, leave notes unwritten and tables in `01-evidence-of-relevance.md` empty.

## Purpose

Collect **sourced** stakeholder input for relevance and requirements (e.g. dermatologist, GP, potential end user). Interviews are optional until the supervisor agrees they are needed.

## Consent (template — confirm legally)

Before recording or storing notes:

- Explain the diploma context and that the app is **not** a diagnostic device.
- State how notes will be stored (this repo vs private folder).
- Do not collect patient-identifiable photos in interviews unless a protocol exists.
- TODO(team): consent form file; whether anonymisation is required.

## Interview guide template

Use the same guide for comparable notes. Adapt questions; do not present unused questions as if they were asked.

1. Date, duration, language, interviewer names.
2. Interviewee **role** (not a fabricated biography). Personal name: store only if consent allows.
3. How do people currently get a first opinion on a skin lesion? (do not prompt a product name unless they mention one)
4. What would make a **preliminary** photo classification useful vs harmful?
5. Which outputs are acceptable (label, probabilities, “see a specialist” only)?
6. Privacy concerns about storing skin photos.
7. Languages needed.
8. Anything that must never be claimed by a student app.
9. Closing: permission to quote, and whether the note may be committed to git.

## How to file a note

1. Copy `interview-note-template.md` to `interview-YYYY-MM-DD-<role>.md` only after a real interview.
2. Link the file from `docs/01-evidence-of-relevance.md`.
3. Prefer role + date in the filename if the person must stay anonymous.
